Context & Architecture

302 U.S. bank holding companies, 97 quarters of Y-9C regulatory data (2002–2026). Goal: predict every income statement and balance sheet line item using lagged balance sheet items + macro covariates, with per-target RFECV feature selection, multiple model families, SHAP explainability, MLflow tracking, and Gradio dashboard integration.

Key architectural split:
Tree models (XGBoost, LightGBM): per-bank — separate model per institution × target. 302 × ~91 ≈ 27,400 models. Requires parallelism.
Neural models (TFT, DeepVAR): global multi-entity — designed for cross-bank pooling; 97 rows/bank is too few for a transformer/RNN individually. TFT uses bank-level static covariates; DeepVAR jointly models all targets.

Key Design Decisions

#DecisionChoice
1Income statement representationConvert YTD → quarterly via within-year diff before any feature engineering (port _convert_ytd_to_quarterly from gradio_dashboard.py:27)
2Predictor groupsHard-coded economic logic — each target mapped to an allowed set of balance sheet lags + FRED series (see Step 1)
3Feature selectionRFECV per-bank per-target using TimeSeriesSplit; step estimator = LightGBM
4Cross-validationTimeSeriesSplit(n_splits=5, min_train_size=20)

6Results storageMLflow — experiment per model family, run per bank × target

Step 1 — modeling/config/predictor_groups.py

Define PREDICTOR_GROUPS: dict[str, dict] mapping each target MDRM to its allowed predictor pool.

Each entry: {"balance_sheet_lags": [...], "fred_series": [...], "n_lags": int}. Source MDRM codes from src/y9c/config.py:get_all_mdrm_codes().

Step 2 — modeling/data/prep.py

build_bank_dataset(rssd_id, target_mdrm, predictor_group_cfg) → pd.DataFrame

  • Load from datasets.load_joined(), filter to single bank
  • YTD→quarterly: diff income statement columns within year (port from gradio_dashboard.py:27-34)
  • Select columns: target + allowed predictors only
  • Drop rows with NaN in target; forward-fill predictors (max 2 quarters)
  • Return tidy (T × features) DataFrame sorted by date with report_date as index
Step 3 — modeling/features/engineer.py

add_features(df, target_col, predictor_group_cfg) → (X, y, feature_names)

Three distinct lag groups, all grouped by rssd_id:

Feature groupWhat gets laggedDetail
Predictor lagsEach balance sheet predictor in the group configlag1…lagN (default N=4) + rolling mean 4Q, 8Q per predictor
Target own-lags (AR)The target variable itselflag1…lagN — captures momentum / mean-reversion
FRED covariatesCurrent-quarter economic seriesUsed as-is — known at prediction time, no lag needed
  • Raw (t=0) values of predictors and target are excluded — only lagged/rolling to prevent look-ahead leakage
  • Drop first n_lags rows per bank (NaN from lags)
  • Add cyclical quarter encoding (sin/cos)
  • Reuses _add_lags / _add_rolling from src/y9c/models/xgb.py:43-69
Step 4 — modeling/data/cv.py

make_cv_splits(n_obs, n_splits=5, min_train=20) → TimeSeriesSplit

  • Wraps sklearn.model_selection.TimeSeriesSplit, enforces min_train_size=20
  • rolling_cv_score(estimator, X, y, cv, metrics) → per-fold metrics dict
Step 5 — modeling/features/selector.py

select_features(X, y, cv, n_jobs=-1) → list[str]

  • RFECV(estimator=LGBMRegressor(n_estimators=100), cv=cv, scoring="neg_mean_absolute_error")
  • Caches result to MLflow as selected_features.json so reruns skip selection
  • Parallel via n_jobs — each bank×target call is independent

Step 7 — modeling/models/xgb.py and lgbm.py

Per-bank wrappers implementing ForecastModel. Serialise with joblib. Support horizon=1 (extend to multi-horizon via recursive prediction).

Step 8 — modeling/explain/shap_explain.py

compute_shap(model, X, max_rows=500) → pd.DataFrame

  • shap.TreeExplainer for XGB/LGBM
  • Returns (rows × features) SHAP value DataFrame
  • Logs mean |SHAP| bar chart + summary_plot PNG to MLflow
Step 9 — modeling/models/tft.py Global

Uses PyTorch Forecasting TemporalFusionTransformer.

  • Static categoricals: rssd_id (bank identity)
  • Static reals: log(total_assets) as bank size
  • Time-varying known reals: FRED series
  • Time-varying unknown reals: Y-9C target columns (observed to time t)
  • max_prediction_length=4, max_encoder_length=20
Step 10 — modeling/models/deepvar.py Global

Uses GluonTS DeepVAREstimator. Jointly models all target series per bank. Reuses src/y9c/models/deepar.py:prepare_deepar_data() as data prep base. prediction_length=4, context_length=20.

Step 11 — modeling/pipeline.py

run_pipeline(rssd_ids=None, targets=None, models=["xgb","lgbm"], n_jobs=4)

  • Outer loop: Parallel(n_jobs)(bank × target) via joblib
  • Per iteration: build dataset → add features → select features (or load cached) → rolling CV → fit → SHAP → log to MLflow
  • Neural models (TFT, DeepVAR) run as separate global pass after per-bank loop
  • MLflow: experiment = {model_type}, run name = {rssd_id}__{target_mdrm}
Step 12 — modeling/explain/neural_explain.py

TFT attention weight extractor. Calls model.interpret_output() from pytorch-forecasting. Extracts variable importance + attention patterns → saves as JSON artifact in MLflow.

Scale Note

Per-bank × per-target RFECV ≈ 27,400 runs. At 30s each → ~230 CPU-hours. Mitigations:
  • Cache RFECV results as MLflow artifacts — reruns skip selection
  • Use n_jobs=4–8 parallelism on local machine
  • Start with a priority subset (USAA + top-10 by assets) before full run
